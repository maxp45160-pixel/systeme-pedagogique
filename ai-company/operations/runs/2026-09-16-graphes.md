# Graphes pour les agents — enquête du 16 septembre 2026

Demande : examiner l'intérêt de Graphify en complément des graphes existants,
le raccordement possible aux agents et l'économie de contexte. Ce document
conserve une enquête et une recommandation, pas une adoption ou un changement
de permissions. Aucun composant produit ni configuration globale modifié.

## Conclusion proposée

Conserver les graphes de parcours Twiny et leur ajouter un accès ciblé pour
les agents ; utiliser un seul index technique pour les symboles et appels.
Essayer d'abord `codebase-memory-mcp` 0.9.0 déjà installé. Graphify recouvre
largement ce second besoin ; son installation n'est pas nécessaire pour
vérifier cette combinaison. Un besoin distinct de relations entre documents
pourrait justifier une autre évaluation ultérieure.

## Essai technique local

Base observée : commit `ee021996692a29e042a25a328319003b4c3bb18e`.
Copie isolée de 517 fichiers suivis (sources TypeScript hors tests et fichiers
de configuration sélectionnés), sans secrets, corpus documentaire ou données
personnelles. L'essai ne constitue pas une indexation du dépôt complet.

Exécutable : `C:/Users/Maxime/.local/bin/codebase-memory-mcp.exe`.
Répertoire temporaire de l'essai :
`C:/Users/Maxime/AppData/Local/Temp/twiny-graph-trial-liYKH7`.
Le manifeste et les sorties brutes y sont conservés, mais cet emplacement
temporaire n'est pas une mémoire durable. Les résultats utiles suivent.

Configuration du processus : `CBM_CACHE_DIR` vers `cache/`,
`CBM_ALLOWED_ROOT` vers `corpus/`, `CBM_WORKERS=2`, UI et surveillance
automatique désactivées dans cette configuration isolée. La CLI a indexé
5 086 nœuds et 18 525 liens en 5,379 secondes ; base de 25 624 576 octets.
Aucun appel à un fournisseur LLM effectué par l'essai. Le coût propre de la
conversation Codex n'est pas mesuré.

Requête exécutée via `cli query_graph`, avec le projet temporaire sélectionné :

```cypher
MATCH (caller:Function)-[:CALLS]->(target:Function)
WHERE target.name = 'envTuteur'
RETURN caller.name, caller.file_path, caller.start_line LIMIT 100
```

Huit appelants retrouvés et confrontés à la recherche textuelle et au code :
`resoudreMoteur`, `appelerQwen`, `appelerMistral` et les routes POST
`referentiel/relecture`, `referentiel/tags`, `referentiel/carte`,
`projets/generer`, `referentiel/relations`. Les lignes retournées désignent
le début de la fonction appelante, pas nécessairement la ligne de l'appel.

| Question identique, corpus identique | Sortie graphe | Recherche `rg` |
|---|---:|---:|
| Occurrences/appelants de `envTuteur` | 562 caractères | 2 040 caractères |
| Occurrences/appelants de `scannerWorkflow` | 208 | 318 |
| Occurrences/appelants de `TableauBordOrchestration` | 187 | 107 |

Ces sorties ne contiennent pas la même information : `rg` restitue également
imports, commentaires et déclaration. Le graphe n'est pas toujours plus court.
Ce sont des caractères, pas des tokens ni un coût total de mission.

**Contre-exemple constaté :** l'index attribue à `scannerWorkflow` un appel
à elle-même alors que l'expression à la ligne 286 est `analyses.get`.
L'arête annonce `strategy=callee_suffix`, `confidence=0.50`. Le véritable
appel depuis `ContenuAdmin` annonce `lsp_ts_import`, `0.95`.
Une lecture ciblée du code reste obligatoire avant de conclure à une
dépendance ; un seuil de confiance seul ne garantit pas l'exactitude.

Essai du sous-agent CTO : scanners et BFS existants exécutés en mémoire,
sans nouvelle dépendance. Racine `page:/seances`, profondeur 1, liens de
cadre retirés avant parcours, projection id/type/libellé et extrémités/type.

| Vue | JSON complet | Projection |
|---|---:|---:|
| Architecture | 66 347 caractères | 20 184 |
| UX atomique | 146 562 | 13 786 |
| Macro | 6 348 | 432 |

La projection atomique contient 56 nœuds et 106 liens. Cette expérience
élimine volontairement des détails : un véritable accès agent doit préserver
conditions et indicateurs heuristiques utiles à la question. Le BFS actuel
n'impose pas de profondeur maximale et l'export JSON inclut les nœuds
inatteignables. Les brancher tels quels ne borne donc pas le contexte.

## Premier raccordement recommandé, non implémenté ici

1. Un point d'entrée local aux scanners existants, avec vue, racine,
   profondeur et limites explicites de taille ; signaler toute troncature.
   Ajouter ensuite la provenance fichier/ligne là où elle est disponible.
2. Accès technique par la CLI déjà testée, ou activation du MCP existant
   après accord sur sa configuration. Une indexation du dépôt vivant doit
   maîtriser les fichiers exclus, le cache et les écritures annexes : l'essai
   en copie ne vaut pas autorisation de les produire partout.
3. Instruction ciblée aux agents : parcours utilisateur → graphe Twiny ;
   appelants/dépendances → index technique ; affirmation décisive → source.
   Lire un sous-graphe à la demande, jamais tout le graphe au démarrage.
4. Comparer plusieurs missions fixes avec/sans accès, en mesurant lectures,
   tokens lorsqu'ils sont disponibles, erreurs et temps. Conserver les
   contre-exemples ; ne pas annoncer un pourcentage global avant mesure.

Ce raccordement ne requiert ni fusion des bases, ni nouveau framework,
ni Graphify en plus d'un index technique équivalent. Il reste une proposition
issue de la demande d'enquête ; aucune activation automatique déclarée.
