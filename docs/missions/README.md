# Missions ③ à ⑩

Ces missions sont le canal de continuité entre agents : chacune est autonome, versionnée, et produit un livrable nommé. Lire `AGENTS.md`, `PRODUCT.md`, `PRODUCT_SPECIFICATION_MAP.md` et `ARCHITECTURE_DECISIONS.md` avant de démarrer.

## Ordre et chaînage

Exécuter, dans cet ordre : ③ remplir les briques, ④ questions ouvertes, ⑤ modèle théorique, ⑥ audit Codex (en parallèle avec l'audit Claude), ⑦ fusion, ⑧ roadmap, ⑨ implémentation, ⑩ ré-audit.

Une mission ne commence que lorsque le livrable de la mission précédente est commité. L'étape ⑦ attend les deux audits, chacun produit indépendamment et sans lecture de l'autre avant leurs commits. Les arrêts humains sont obligatoires après ④, après ⑦, et pour toute montée de statut pendant ⑨.

Règle d'or : une analyse n'est jamais une décision validée. Seule une personne, explicitement, peut passer un statut en ✅.

Chaque mission applique ce gabarit : objectif, entrées, livrable, méthode, critères de refus et vérification.
